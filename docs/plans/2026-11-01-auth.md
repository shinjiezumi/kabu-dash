# 実装計画: 認証機能（ログイン・ログアウト・登録・パスワード再発行・メール確認）

- 作成日: 2026-11-01
- ステータス: 未着手
- 位置づけ: `2026-07-20-auth*.md`（5本）の統合・修正版。**内容が矛盾する場合は本書を優先する。**

## 要件

Laravel Fortify を使い、Blade の MPA で認証画面を実装する。2要素認証・パスキー・プロフィール更新・ログイン中のパスワード変更はスコープ外。PR は Phase ごとに分け、番号順に実装する。

| Phase | 内容 | 依存 |
|-------|------|------|
| 1 | Fortify 導入・ログイン・ログアウト | なし |
| 2 | ユーザー登録 | 1 |
| 3 | パスワード再発行 | 1 |
| 4 | メールアドレス確認 | 1, 2 |

### 受け入れ条件

**Phase 1: ログイン・ログアウト**

- 正しいメールアドレスとパスワードでログインすると `/dashboard` に遷移する
- 誤った認証情報ではログインできず、メールアドレスの登録有無が区別できないエラーを表示する
- 同一メールアドレス + IP で 1 分間に 5 回を超えて試行すると 429 を返す
- ログアウトするとセッションが破棄され、`/dashboard` にアクセスすると `/login` へリダイレクトされる
- スコープ外の機能のルートが登録されていない

**Phase 2: ユーザー登録**

- 名前・メールアドレス・パスワードで登録すると、そのままログイン状態になる
- メールアドレスは小文字化して保存し、大文字小文字だけが異なるメールアドレスは重複として拒否する
- パスワードの不一致や強度不足はバリデーションエラーになる

**Phase 3: パスワード再発行**

- 登録済みメールアドレスには再設定リンクを送る
- 未登録のメールアドレスと、短時間に再送した登録済みメールアドレスにも、送信成功時と同じメッセージを表示する（登録有無を判別させない）
- リンクから新しいパスワードを設定でき、以後そのパスワードでログインできる
- リンクは 60 分で失効し、使用後は無効になる

**Phase 4: メールアドレス確認**

- 登録直後に確認メールを送る
- 署名付きリンクを開くと `email_verified_at` が設定される
- 未確認ユーザーはログイン状態を維持するが、`/dashboard` にアクセスすると確認案内画面へリダイレクトされる
- 確認案内画面から確認メールを再送できる

## ドメイン設計

新規のドメインモデルは作らない。認証の中核は Laravel / Fortify に任せるという 2026-07-20 の判断を引き継ぐため、`ddd-modeler` は実行していない。

- **実装の置き場所**: 自作コードは `src/app/Actions/Fortify/`、`src/app/Http/Responses/`、`FortifyServiceProvider` に閉じ込める
- **コード規約**: `declare(strict_types=1)` と `final` は自作クラスに適用する（Fortify のスタブは満たしていないため手書きする）
- **規約との整合**: `docs/architecture.md` に適用除外を明記する（Phase 1）

## リスク・確認事項

### 2026-07-20 版からの修正点（Fortify `1.x` ブランチのソースで確認済み）

| # | 旧計画の記述 | 確認した事実 | 本書の対応 |
|---|------------|------------|----------|
| 1 | `--provider` 指定で publish し、Features は「全てコメントアウトのまま」 | `--provider` だと config に加えて Action スタブ 5 本、Provider、2FA・パスキーのマイグレーションまで出力される。スタブの config は registration / resetPasswords / updateProfileInformation / updatePasswords / 2FA / passkeys が**有効** | `--tag=fortify-config` に限定し、`features` を空にする |
| 2 | `home` の変更に記載なし | 既定は `/home`。そのままだとログイン後に 404 になる | `/dashboard` に変更 |
| 3 | 未登録メールでも同じ完了メッセージが出る（Fortify 標準） | **標準では出ない。** broker が `INVALID_USER` を返すと失敗レスポンスになり、`email` エラー付きで戻るため登録有無が判別できる。再送時の `RESET_THROTTLED` も登録済みの場合にしか返らない | 失敗レスポンスを差し替える |
| 4 | `POST /forgot-password` に `throttle:6,1` が付く | ルートのミドルウェアは `guest` のみ | 記述を削除。登録済みアドレスへの連続送信は broker の 60 秒制限で抑えられ、未登録宛にはメールを送らないため、追加しない |
| 5 | `User` にトレイトも追加 | 親クラスが使用済み | `implements` のみ |

あわせて確認できた点:

- `laravel/fortify` の `1.x` は `illuminate/*` の `^13.0` と PHP `^8.2` に対応している
- スタブの config は `lowercase_usernames => true` で、ログイン・登録・再発行リンクの各経路で小文字化される。そのため `CreateNewUser` に独自の小文字化は入れない（`CreateNewUser` を HTTP 経由以外で呼ぶ場合は小文字化されない）

### リスク

1. **config の設定漏れ**: `features` を空にし忘れると、2FA 等のルートが公開される。`DisabledFeaturesTest` で検知する
2. **不要な依存**: Fortify は未使用でも `laravel/passkeys`、`pragmarx/google2fa`、`bacon/bacon-qr-code` を引き込む。CI の `composer audit` の対象が増える
3. **ソース確認の範囲**: 上記の確認は `1.x` ブランチに対するもので、実際に入るタグとは差がありうる。導入後に `vendor/laravel/fortify` と `route:list` で再確認する
4. **再設定メールの列挙耐性は完全ではない**: `POST /reset-password` の失敗メッセージは標準のまま。有効なトークンがないと実害が小さいため、今回は対応しない
5. **テストと実環境の差**: テストは SQLite + array セッション、実環境は PostgreSQL + database セッションで、secure cookie も有効な想定。`php artisan serve`（http）ではセッションが維持できない可能性があるため、手動確認は https で行う
6. **`intl` 拡張なし**: `docker/php/Dockerfile` に `intl` がなく、`php artisan db:table` は失敗した。`test --coverage` への影響は未確認のため、着手前に確認する
7. **公開範囲**: README は「ローカル個人利用のみ」だが、`compose.yml` は 80 / 443 / 5432 を全インターフェースに公開している。Phase 2 以降は同一 LAN から誰でもアカウントを作成できる。本計画では変更しない
8. **メール確認の動作確認**: メールの実送信設定は `.env` 側の運用作業でスコープ外。ログ出力の場合、リンクは `APP_URL` を基に生成される
9. **Seeder**: `DatabaseSeeder` は `test@example.com` を無条件に作成するため、2 回目の実行は unique 違反になる見込み（未実行）。本計画では変更しない

### 実装前に確認したい点（未回答の場合は既定で進める）

| 項目 | 既定 | 別案 |
|------|------|------|
| パスワード強度 | Laravel 標準（`Password::defaults()`、最低 8 文字） | 大文字・数字・記号を必須にする |
| 表示言語 | 画面の文言は日本語、バリデーション・認証エラーは英語（`lang/` は追加しない） | `lang/ja` を追加して日本語化する |
| 暫定 `/dashboard` | 追加する（`welcome.blade.php` がログイン済みの場合にリンクするため、ないと 404 になる） | なし（ダッシュボード本体を先に実装する） |
| 未確認ユーザーの扱い | ログイン状態は維持し、`verified` を付けたページのみ制限する | 確認まで完全にログイン不可とする（Fortify の標準から外れる） |
